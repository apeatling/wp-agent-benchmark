How this is measured

    What the agents were asked.

    Two agents tried every prompt, with and without the MCP adapter.

    One prompt up close, with and without the MCP adapter.

    With the MCP adapter, agents could only do what had been made an ability.

    The setups gave agents different ways into the same site. Without the MCP adapter, the owner handed over their login for WordPress’s built-in API. With it, the adapter was the only way in.

    Why it worked so well without the MCP adapter

    WordPress’s built-in API already covers nearly everything an owner can do in the dashboard, and plugins add their own parts to it when they’re installed. Agents know it well, and in these runs they used WooCommerce’s, Redirection’s and three other plugins’ without being told how.

    The MCP adapter starts with only what has been written as an ability. WordPress’s own three only read site, user and server information, and only a few plugins have added any yet. Neither the agents nor MCP were the problem: the abilities just haven’t been written yet.
