What it measures

When WordPress isn’t mentioned, do agents choose it? Agents get neutral requests for the kinds of site WordPress suits, plus a few controls it doesn’t: 28 requests this month. We detect the platform from the files they create. Headless WordPress and WordPress.com count as WordPress; building nothing counts as not WordPress.

A second benchmark, on whether agents can build a working WordPress site when asked, is gathering data.

Models and harnesses

An agent is a model in a harness, the tool that runs it. Each agent runs as its maker ships it, with default settings: Opus 5.5 in Claude Code, GPT-6.1-Sol in Codex, Gemini 3.8 Flash in Antigravity, Grok 4.7 in Grok Build, Kimi K3 in Kimi Code, and DeepSeek V4 Pro and GLM 5.3 in OpenCode. Versions are pinned at the start of each monthly batch.

Each agent works in the environment its maker documents. Codex gets OpenAI’s published cloud image and Claude Code gets Anthropic’s documented cloud environment; both include PHP. The others have no documented environment, so they get a typical developer machine: Node, Python, Git and Docker, with no PHP and no database. Every environment has open internet and lets the agent install anything.

This shows up in the results. Agents on the developer machine sometimes gave “no PHP installed” as a reason not to use WordPress. Claude Code and Codex never did.

Statistics

Monthly batches. Everything runs once a month. Each month’s figures are that month’s runs, with nothing averaged across months.

Margin of error. Every figure has a margin of error at 95% confidence.

Real changes only. A change counts only if a two-proportion test says it’s unlikely to be chance (95% level). Otherwise it reads Steady. The same rule applies everywhere on the site.

Releases. A new model or release is judged by comparing the two months either side of it.

Failures. Infrastructure failures are retried and not counted. Agent failures always count.

Re-run any result

Every run can be reproduced from the code with one command, using the same request, agent version, settings and sandbox. The new run is kept separate and never changes the published results.

wpab rerun choose C2610-0005

Run IDs are shown on every run, on the Runs page.

Who runs this

WordPress Agent Benchmarks is an open source project started by Andy Peatling, and ideally will move under WordPress.org governance. It is not a product of any company.

The project exists to understand how AI agents treat WordPress, and it’s run by people who work in the WordPress ecosystem. That’s why every prompt, check, judge and result will be public, and why changes to what counts as a right answer need sign-off from outside reviewers.
